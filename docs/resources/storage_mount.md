# dokku_storage_mount (Resource)

Attaches, detaches or replaces storage mounts on a dokku application

### Requirements

- Dokku >= 0.38.31

### Export support

Supported.

### Probe support

Supported.

### Lifecycle

Applied with state `set` and torn down with state `clear`, which refuses `entry_name`, `host_dir`, `container_dir`, `phases`, `subpath`, `readonly`, `volume_chown`, `volume_options`, and `mounts`, so a teardown resets them. See [Applying and tearing down a task](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#applying-and-tearing-down-a-task).

### Identity

Keyed by `app`, `container_dir`, and `process_type`. Fields left empty are omitted from the address. Manages the whole `mounts` collection; entries are identified by `container_dir`.

### Objects

- The app named by `app`.

Tasks applied at once on the same object take turns; see [Running tasks concurrently](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#running-tasks-concurrently).

### Constraints

- `mounts` must not be set together with `entry_name`, `host_dir`, `container_dir`, `phases`, `subpath`, `readonly`, `volume_chown` or `volume_options`.
- `entry_name` must not be set together with `host_dir`.
- `entry_name` requires `container_dir`.
- `host_dir` requires `container_dir`.
- Each `mounts` item: exactly one of `entry_name` or `host_dir` must be set.

## Example Usage

```terraform
resource "dokku_app" "node_js_app" {
  app = "node-js-app"
}

resource "dokku_storage_entry" "node_js_app_data" {
  name  = "node-js-app-data"
  chown = "herokuish"
}

# Declare the complete set of mounts for an app, removing any other
resource "dokku_storage_mount" "example" {
  app = dokku_app.node_js_app.app
  mounts = [{
    container_dir = "/app/storage"
    entry_name    = "node-js-app-data"
    }, {
    container_dir  = "/app/uploads"
    host_dir       = "/var/lib/dokku/data/storage/node-js-app"
    volume_options = "Z"
  }]
  depends_on = [dokku_storage_entry.node_js_app_data]
}

# Declare the web process's mounts, each with its own subpath
resource "dokku_storage_mount" "example_2" {
  app          = dokku_app.node_js_app.app
  process_type = "web"
  mounts = [{
    container_dir = "/app/assets"
    entry_name    = "node-js-app-data"
    phases        = ["deploy"]
    readonly      = true
    subpath       = "assets"
    }, {
    container_dir = "/app/cache"
    entry_name    = "node-js-app-data"
    subpath       = "cache"
  }]
  depends_on = [dokku_storage_entry.node_js_app_data]
}
```

## Schema

### Required

- `app` (String) Name of the app

### Optional

- `mounts` (Attributes Set) Attachments of the process_type scope, instead of the single-mount fields. Under state 'set' the list is the scope's complete set of mounts; 'present' adds or updates the listed mounts and 'absent' removes them, leaving the rest of the scope in place. Each item has: entry_name, host_dir, container_dir, phases, subpath, readonly, volume_chown, volume_options. (see [below for nested schema](#nestedatt--mounts))
- `process_type` (String) Process type the attachment applies to. With mounts, the process type whose mounts the list describes; mounts of other process types are left alone. Empty means dokku's _default_ scope.

### Read-Only

- `id` (String) The resource's identity address, such as `dokku_storage_mount[app=api]`.

### Nested Schema for `mounts`

Required:

- `container_dir` (String) Absolute container directory to mount; no two mounts in a list may share one

Optional:

- `entry_name` (String) Named storage registry entry to attach
- `host_dir` (String) Host directory to mount in the legacy bind-mount form, docker-local apps only
- `phases` (Set of String) Deployment phases the attachment applies to (deploy, run). Empty defers to the dokku default. (no duplicates)
- `readonly` (Boolean) Mount the attachment as read-only
- `subpath` (String) Subpath within the entry to mount; must not contain ','
- `volume_chown` (String) Chown option applied to the volume at mount time; must not contain ','
- `volume_options` (String) Comma-separated Docker mount options (e.g. 'Z', 'noexec,nosuid'). A key=value option and ro/rw are not accepted in a list; use readonly for ro.
