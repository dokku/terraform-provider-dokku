# dokku_certs (Resource)

Manages SSL certificates for a dokku app or globally.

### Requirements

- Dokku >= 0.38.28
- dokku-global-cert plugin >= 0.7.0 (required only when global: true)

### Export support

Partial - app and global certificate PEM material is exported (via certs:show and global-cert:show) and written to the companion vars-file.

### Probe support

Partial - a certificate is compared against the desired one by the SHA-256 fingerprint its report carries - certs:report for an app, global-cert:report --global for the global certificate - falling back to reading the PEM back with certs:show or global-cert:show when the recipe pins a certificate chain or the report carries no usable fingerprint; on the fingerprint path a server holding the pinned certificate plus an extra chain reads as in sync, since dokku digests only the first certificate it finds; the private key is never read back, so a key rotated under an unchanged certificate plans as in sync; a cert file path is only compared when docket can read the file from the machine it runs on, which a run against --host cannot; and a letsencrypt-managed certificate is left uncompared.

### Lifecycle

Applied with state `present` and torn down with state `absent`. See [Applying and tearing down a task](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#applying-and-tearing-down-a-task).

### Identity

Keyed by `app` and `global`. Fields left empty are omitted from the address.

### Objects

- The app named by `app`.

Tasks applied at once on the same object take turns; see [Running tasks concurrently](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#running-tasks-concurrently).

### Constraints

- Exactly one of `app` or `global` must be set.
- `cert` must not be set together with `cert_content` or `key_content`.
- `key` must not be set together with `key_content` or `cert_content`.
- At least one of `cert` or `cert_content` must be set.
- `cert` and `key` must be set together or not at all.
- `cert_content` and `key_content` must be set together or not at all.

## Example Usage

```terraform
resource "dokku_app" "node_js_app" {
  app = "node-js-app"
}

# Add an SSL certificate to an app
resource "dokku_certs" "example" {
  app  = dokku_app.node_js_app.app
  cert = "/etc/nginx/ssl/node-js-app.crt"
  key  = "/etc/nginx/ssl/node-js-app.key"
}

resource "dokku_plugin" "global_cert" {
  name = "global-cert"
  url  = "https://github.com/dokku-community/dokku-global-cert.git"
}

# Add a global SSL certificate (requires the dokku-global-cert plugin)
resource "dokku_certs" "example_2" {
  global     = true
  cert       = "/etc/nginx/ssl/global.crt"
  key        = "/etc/nginx/ssl/global.key"
  depends_on = [dokku_plugin.global_cert]
}
```

## Schema

### Optional

- `app` (String) Name of the app
- `cert` (String, Sensitive) Path on the dokku server to the SSL certificate file (applied only, not read back) (sensitive)
- `cert_content` (String, Sensitive) PEM-encoded certificate contents. Export reads it back with certs:show or global-cert:show. (not returned when reading state) (sensitive)
- `global` (Boolean) Flag indicating if the certificate should be applied globally via the dokku-global-cert plugin
- `key` (String, Sensitive) Path on the dokku server to the SSL certificate key file (applied only, not read back) (sensitive)
- `key_content` (String, Sensitive) PEM-encoded private key contents. Export reads it back with certs:show or global-cert:show. (not returned when reading state) (sensitive)

### Read-Only

- `id` (String) The resource's identity address, such as `dokku_certs[app=api]`.
