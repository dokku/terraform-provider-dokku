# dokku_http_auth_user (Resource)

Manages the set of HTTP auth users for a dokku application

### Requirements

- Dokku >= 0.38.31
- dokku-http-auth plugin >= 0.14.0

### Export support

Supported.

### Probe support

Partial - an existing user's htpasswd hash is probed; a cleartext password is not readable, so a user that already exists converges only when update_password forces it.

### Lifecycle

Applied with state `set` and torn down with state `clear`, which refuses `users`, so a teardown resets it. See [Applying and tearing down a task](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#applying-and-tearing-down-a-task).

### Identity

Keyed by `app`. Manages the whole `users` collection; entries are identified by `username`.

### Objects

- The app named by `app`.

Tasks applied at once on the same object take turns; see [Running tasks concurrently](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#running-tasks-concurrently).

### Constraints

- Each `users` item: `password` must not be set together with `hash`.
- Each `users` item: at least one of `password` or `hash` must be set.

## Example Usage

```terraform
resource "dokku_plugin" "http_auth" {
  name = "http-auth"
  url  = "https://github.com/dokku/dokku-http-auth.git"
}

resource "dokku_app" "hello_world" {
  app = "hello-world"
}

resource "dokku_http_auth" "hello_world_http_auth" {
  app        = dokku_app.hello_world.app
  depends_on = [dokku_plugin.http_auth]
}

# Add HTTP auth users to an app
resource "dokku_http_auth_user" "example" {
  app = dokku_app.hello_world.app
  users = [{
    password = "secret"
    username = "admin"
    }, {
    password = "hunter2"
    username = "ops"
  }]
  depends_on = [dokku_plugin.http_auth, dokku_http_auth.hello_world_http_auth]
}
```

## Schema

### Required

- `app` (String) Name of the app

### Optional

- `update_password` (Boolean) Re-issue add-user for users that already exist so their cleartext password converges. Users given by hash converge on their own and ignore this (applied only, not read back)
- `users` (Attributes Set) List of HTTP auth users to add or remove. Each item has: username, password, hash. (see [below for nested schema](#nestedatt--users))

### Read-Only

- `id` (String) The resource's identity address, such as `dokku_http_auth_user[app=api]`.

### Nested Schema for `users`

Required:

- `username` (String) HTTP auth username

Optional:

- `hash` (String, Sensitive) htpasswd hash for the user, as emitted by http-auth:export-users; applied over stdin with http-auth:import-users so it never reaches argv (sensitive)
- `password` (String, Sensitive) Cleartext HTTP auth password, applied with http-auth:add-user (not returned when reading state) (sensitive)
