# dokku_config (Resource)

Manages the configuration for a given dokku application

### Requirements

- Dokku >= 0.38.31

### Export support

Partial - config values are written to the companion vars-file.

### Probe support

Supported.

### Lifecycle

Applied with state `set` and torn down with state `clear`, which refuses `config`, so a teardown resets it. See [Applying and tearing down a task](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#applying-and-tearing-down-a-task).

### Identity

Keyed by `app`. Manages the whole `config` collection; entries are identified by their key.

### Objects

- The app named by `app`. Can restart or redeploy it when `restart` is true.

Tasks applied at once on the same object take turns; see [Running tasks concurrently](https://github.com/dokku/docket/blob/v0.11.0/docs/embedding.md#running-tasks-concurrently).

## Example Usage

```terraform
resource "dokku_app" "hello_world" {
  app = "hello-world"
}

# set KEY=VALUE
resource "dokku_config" "example" {
  app     = dokku_app.hello_world.app
  restart = true
  config = {
    KEY = "VALUE_1"
  }
}
```

## Schema

### Required

- `app` (String) Name of the app

### Optional

- `config` (Map of String) Map of configuration key-value pairs
- `preserve` (Set of String) Keys that state 'set' and 'clear' leave untouched, on top of the service-link keys, NO_VHOST, and the git rev-env-var key they always keep (no duplicates) (applied only, not read back)
- `restart` (Boolean) Flag indicating if the app should be restarted (applied only, not read back)

### Read-Only

- `id` (String) The resource's identity address, such as `dokku_config[app=api]`.
